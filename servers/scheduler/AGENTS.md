# scheduler MCP server

Общие правила — в [корневом AGENTS.md](../../AGENTS.md).

- Самостоятельный npm workspace `@mcp-lab/scheduler-server`. Не импортирует host и другие серверы.
- Владеет SQLite, расписаниями, записями опросов и отчётами; host работает с состоянием только через MCP.
- Два режима регистрации: публичный (`schedule_weather`, `get_weather_summary`, `cancel_weather_schedule`) и
  `--worker` (служебные `worker_*`). Режимы не смешиваются: служебные операции не попадают в список Agent.
- `process`, argv и env — только в `src/app/main.ts`; `--db` и `--reports-dir` — абсолютные пути.
  Часы и генератор ID передаются через DI.
- stdout — только MCP protocol; любой лог — только stderr. Текст ошибки хранилища клиенту не отдаётся.
- База открывается при первом обращении к ней: пробный процесс согласования версии MCP не создаёт файлов
  и не берёт блокировку. Право worker занимает только `worker_start`.
- Блокировка worker — эксклюзивная транзакция SQLite на файле рядом с базой; объект должен оставаться достижимым.
- Транзакции короткие (`BEGIN IMMEDIATE`), сетевых и модельных вызовов внутри них нет.
- Источник текста сводки — SQLite; `.md` — копия, которую заменяют через временный файл и rename.
- Сроки: первый — `createdAt + интервал`; после простоя операция выполняется один раз, срок — от фактического запуска.
- Тесты используют временные каталоги и управляемые часы; внешних API нет.
