# Направления курса

Это ориентиры репозитория. Конкретные задания будут предоставлены отдельно.

1. Роли host/client/server, tools/resources/prompts, stdio и Streamable HTTP, жизненный цикл.
2. Собственные MCP-серверы поверх публичных API и локальных инструментов.
3. Оркестрация нескольких серверов собственным host.
4. Использование серверов из Claude Code, Codex и других клиентов.
5. Сравнение MCP с Skill + CLI на одном host, одной модели и одинаковых задачах.

Discovery Filesystem-сервера по stdio, native tool calling (`get_current_weather` собственного Open‑Meteo
server, максимум один tool call за реплику) и планировщик погоды с worker в host (ADR 0004) уже
реализованы. До следующих заданий не добавлять новые server-заглушки, tool rounds, общий агрегатор
нескольких MCP-серверов с политиками, память, конвейер контекста, систему трассировки или runner экспериментов.

## Ориентиры будущих решений

- MCP-клиент отвечает за lifecycle, discovery, имена инструментов, маршрутизацию, подтверждение, таймауты и журнал.
- Источник инструментов заменяемый, но контракт вводится с первой реальной реализацией.
- Составное поведение — именованный упорядоченный список, видимый в конфигурации и трассировке.
- Трассировка показывает шаги, вклад в запрос, usage/оценки и результаты вызовов без секретов.
- Сравнение учитывает объём описаний, LLM-вызовы, tool calls, успешность, задержку и трудозатраты.
- Skills используют SKILL.md; описания и загрузку skill учитывают в расходе контекста.
- Версия MCP SDK и ревизия протокола — разные решения; lifecycle проверяется по выбранной ревизии.
