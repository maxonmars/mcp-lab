# 0006 — Ежедневная сводка погоды через Agent

Статус: принято для задания дня 18.
Дата: 2026-09-27.

## Цель и минимальный результат

По расписанию запустить существующий `Agent` с доступом к данным через MCP и вывести новую сводку без
реплики пользователя. Пример — каждый день в 18:00 по `Asia/Novosibirsk`. Погода и SQLite-состояние
остаются у существующего планировщика; отдельный канал доставки не вводится.

Проверяемый результат: созданное через MCP ежедневное расписание вызывает `Agent.respond()` в срок,
Agent запрашивает накопленные данные через MCP, отчёт сохраняется и появляется в терминале `scheduler run`.
Если Agent не вызвал инструмент или вернул некорректный текст, прежний отчёт сохраняется.

## Контракт и границы

- `servers/scheduler` добавляет публичный `schedule_daily_weather_summary` с городом, интервалом опроса,
  местным временем `HH:mm` и часовым поясом IANA. `schedule_weather` с двумя интервалами остаётся доступен.
- В SQLite хранятся время, пояс и следующий срок ежедневной сводки. Существующие базы версии 1
  обновляются без потери расписаний, опросов и отчётов. После простоя просроченная работа выполняется
  один раз; пропущенные дни не создают фиктивных сводок.
- `features/scheduler` продолжает собирать погоду через Open‑Meteo MCP. В ежедневный срок worker
  вызывает `Agent.respond()` с одним инструментом `get_weather_report_data`. Этот фасад запрашивает
  историю через служебный MCP-инструмент планировщика, считает показатели и отдаёт Agent ограниченный
  Markdown-контекст. Служебные инструменты не становятся публичными.
- Для интервальных расписаний остаётся прежняя генерация через `ModelPort`. Новый путь ограничен
  ежедневным расписанием; ядро, его лимит одного tool call и инструментальный пайплайн `outfit`
  не меняются.
- Поскольку `Agent` использует `toolChoice: "auto"`, выпуск отчёта требует фактического вызова
  `get_weather_report_data`. Ответ без вызова фиксируется как ошибка сводки. Период и число
  наблюдений проверяются перед публикацией, как в интервальном режиме.
- После сохранения worker печатает отчёт в том же терминале. `scheduler summary` и
  `get_weather_summary` читают сохранённый текст без новой генерации.

## Настройки, команды и проверка

Новых настроек и команд нет. Публичный MCP-инструмент принимает часовой пояс явно; команды
`scheduler run` и `scheduler summary` используют существующий реестр. Новые инструкции модели
лежат в Markdown внутри `features/scheduler/prompts`.

Тесты с управляемыми часами проверяют ежедневный срок в 18:00 по `Asia/Novosibirsk`, повторный
запуск после простоя, сохранение при ответе без MCP-вызова и сохранение опубликованного отчёта.
Ручной сценарий описан в `docs/demos/scheduler-agent.md`.

`scheduler run` должен оставаться запущенным. Автозапуск процесса и отправка в мессенджер или почту
не входят в этот результат.
