# 0005 — Пайплайн совета по одежде на сервере Open‑Meteo

Статус: принято и реализовано.
Дата: 2026-09-25.

## Контекст

Учебная цель — последовательно вызвать несколько инструментов одного MCP-сервера через одну сессию,
передавая результат каждого шага следующему без изменений. Минимальный результат: по городу получить
текущую погоду и прогноз на три почасовых интервала, составить совет по одежде и сохранить его в
`<cwd>/.local/outfit/latest.md`. Пайплайн запускается командой `outfit <город...>` или через `ask`.

До этого `servers/open-meteo` регистрировал ровно один инструмент, не хранил состояние, не требовал ключа и
не обращался к модели. Agent допускает один tool call за реплику; `Agent`, `ModelPort` и этот лимит не
меняются.

## Варианты

- Три инструмента в Agent: модель должна сделать три вызова подряд, что противоречит лимиту Agent.
- Цепочка в одном инструменте сервера: шаги не видны как отдельные MCP-вызовы, учебная цель не достигается.
- Runner в host вызывает три инструмента сервера по очереди; для `ask` модель видит один фасад, который
  запускает тот же runner.

## Решение

- Сервер Open‑Meteo получает два режима. Обычный регистрирует только `get_current_weather` и работает
  без ключа и файла; его использует worker планировщика. Флаг `--outfit-report-file <абсолютный путь>`
  добавляет `recommend_outfit` и `save_outfit_advice`.
- `get_current_weather` получает необязательный `includeNextHours`. Без него запрос к API, текст и
  `structuredContent` прежние. С ним после получения текущей погоды выполняется отдельный hourly-запрос
  (`forecast_hours=5`, `timeformat=unixtime`) без повторного геокодирования; выбираются три первые
  отметки строго позже текущего времени и `observedAtUtc`. Температура, ощущаемая температура, ветер и
  состояние относятся к отметке, осадки и их вероятность — к часу перед ней
  ([Open‑Meteo](https://open-meteo.com/en/docs)). Неполный прогноз — ошибка прогноза, а не нули.
- `recommend_outfit({weatherText})` делает один запрос к DeepSeek собственным серверным адаптером:
  без reasoning, без повторов SDK, с моделью, таймаутом и лимитом токенов host. Инструкция модели — Markdown
  сервера. Сервер добавляет к совету заголовок и раздел с исходным `weatherText`.
- `save_outfit_advice({markdown})` записывает текст без изменений в заданный при запуске файл через
  временный файл рядом и `rename`; путь в MCP-аргументах отсутствует.
- Фича host `features/outfit` содержит runner, проекцию источника для Agent с фасадом
  `prepare_outfit_advice` и параметры запуска сервера. Внутренние шаги скрыты от Agent и не вызываются
  через проекцию. Команда и фасад используют один runner.
- `withStdioToolSource` принимает `env` и таймауты вызова по имени инструмента. MCP SDK по умолчанию
  передаёт дочернему процессу только безопасный набор переменных, поэтому `LAB_LLM_*` передаются явно.

## Последствия

Сервер Open‑Meteo теперь может обращаться к DeepSeek и писать один файл, но только в outfit-режиме.
Каждый `ask` запускает Open‑Meteo в этом режиме: Agent получает фасад, а процессу нужен ключ, который
`ask` и так требует. Модель в `ask` может не выбрать фасад; гарантированный порядок даёт команда.
Статусы `MCP:` печатаются для трёх реальных вызовов, фасад как MCP-инструмент не показывается.
Профиль, гардероб, история советов и новые настройки не добавляются.

## Проверка

Офлайн-тесты сервера: неизменность старого вызова, выбор интервалов посреди часа, на границе часа и через
полночь, отказ при неверных массивах, времени и неполном прогнозе; один инструмент в обычном режиме и три
в outfit-режиме; один запрос модели без повторов; точное содержимое файла, замена прежнего и отсутствие
временного файла после отказа. Тесты host: порядок и дословная передача, остановка после ошибки каждого
шага, одна сессия, скрытие внутренних шагов, три статуса, команда в CLI и REPL, выбор фасада fake
`ModelPort`. Ручное демо — [docs/demos/outfit.md](../demos/outfit.md).
