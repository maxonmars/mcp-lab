# 0002 — Получение списка инструментов Filesystem MCP

Статус: принято для первого подключения MCP.
Дата: 2026-09-22.

## Контекст

Host должен показать первое настоящее MCP-соединение без участия LLM: запустить локальный
Filesystem-сервер, выполнить инициализацию, получить список инструментов и корректно завершить
дочерний процесс. Выполнение инструментов, их схемы в модели и общий источник инструментов в
объём не входят.

## Варианты

Можно было бы создать учебный сервер в `servers`, подключиться к удалённому серверу или использовать
Filesystem MCP через stdio. Собственный сервер расширил бы задание второй реализацией, а удалённый
сервер потребовал бы сеть и учётные данные.

## Решение

- Фича `apps/host/src/features/mcp` экспортирует одну операцию discovery и собственные типизированные
  ошибки через `index.ts`.
- Команда host `mcp tools` — единственный потребитель операции; composition root явно передаёт ей
  путь Node, рабочий каталог и настройки.
- Используются `@modelcontextprotocol/client` 2.0.0 и
  `@modelcontextprotocol/server-filesystem` 2026.8.31. Версия SDK не заменяет ревизию протокола:
  transport использует `versionNegotiation.mode = legacy` с
  `supportedProtocolVersions: [2025-11-25]`.
- Сервер запускается как отдельный дочерний процесс Filesystem-пакета через stdio. Вызов discovery
  создаёт собственные Client и Transport, владеет ими до завершения операции и закрывает их в `finally`.
- Фича возвращает сведения, полученные от MCP-сервера, и список его инструментов. CLI сортирует и
  отображает эти данные, но не импортирует MCP SDK.
- Новый контракт ядра не нужен: Agent и ModelPort не участвуют, а операция имеет единственного
  конкретного потребителя и остаётся внутри предметной фичи.

## Последствия

Команда доступна без ключа модели, не создаёт ModelPort и не вызывает LLM. Корень Filesystem
проверяется до запуска процесса; относительное значение настройки разрешается от cwd host.
Повторный вызов создаёт новое соединение, постоянная сессия, кэш, retries и tool calling не появляются.

## Проверка

Тесты подменяют SDK на границе фичи для ошибок lifecycle и времени ожидания. Отдельный
интеграционный тест запускает установленный Filesystem-сервер, получает его реальные инструменты и
проверяет завершение процесса. CLI, REPL и собранный вход проверяют работу без LLM и из другого cwd.
