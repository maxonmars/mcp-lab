# 0001 — Основа репозитория

Статус: принято по подтверждению создания и уточнению первого старта.
Дата: 2026-09-21.

## Контекст

Нужны новый простой агент, пустой CLI и границы для дальнейших учебных заданий.
Пять направлений курса не являются текущим объёмом реализации.
Код и фичи прежнего репозитория не переносятся; сохраняются технологические практики.

## Варианты

Один пакет проще в запуске, но объединяет зависимости будущих серверов.
Пакет на каждую фичу или порт создаёт лишние сборочные связи.
Компактные npm workspaces отделяют процессы при общем tooling.

## Решение

- npm workspaces: сейчас только apps/host, servers/* подключаются по будущим заданиям.
- Node 24, TypeScript, Biome, Vitest, GitHub Actions и обычный Git pre-commit hook.
- Agent инкапсулирует ModelPort и системную инструкцию, не хранит историю и не выполняет tools.
- Один запрос модели на реплику; SDK retry и reasoning отключены явно.
- Один composition root; core не зависит от SDK, UI и инфраструктуры.
- Текущий контракт расширения — ModelPort; остальные вводятся под конкретную потребность через ADR.
- Настройки — общий реестр схем и defaults; файл YAML, затем env, затем CLI.
- Секреты только в env; значения исключены из вывода, ошибок и файлов конфигурации.
- Команды CLI/REPL используют один реестр и dispatcher.
- Промпты и содержательная справка — Markdown; документация реестров генерируется.
- Dependency-cruiser проверяет граф, TypeScript Compiler API — размеры функций и файлов.
- TypeScript 5.9.3 выбран для стабильного Compiler API; переход на 7 требует проверки tooling.
- Coverage — отчёт; значимые сценарии и архитектурные отрицательные тесты обязательны, общего процента нет.

## Последствия

Серверы будут запускаться отдельно и не смогут импортировать host.
Новая предметная фича живёт в собственной папке и выходит наружу через index.ts.
Некоторые изменения ядра неизбежны при новых учебных целях: они проходят ADR, а не маскируются флагами.
Markdown-ресурсы входят в сборку и проверяются при запуске из другого cwd.
Полный pre-commit может занимать больше времени, чем staged-lint; для небольшого проекта это приемлемо.
Внешние API не нужны для тестов; фактический ответ DeepSeek проверяется вручную с пользовательским ключом.

## Проверка

npm run check выполняет lint, typecheck, границы, структуру, документацию, тесты и сборку.
Отрицательный тест добавляет import type между фичами, проверяет отказ, удаляет импорт и проверяет успех.
Отдельно проверяются импорт внутреннего файла, цикл, Node API в core и импорт по имени workspace.
