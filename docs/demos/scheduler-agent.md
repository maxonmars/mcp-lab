# Ежедневная сводка погоды через Agent

Цель: создать ежедневное расписание через MCP и увидеть, как в назначенное время worker запускает
Agent с MCP-данными и печатает новую сводку без пользовательской реплики.

Нужны Node 24, `npm ci` и `LAB_LLM_API_KEY`. Выполняйте команды из корня репозитория в двух терминалах.

## Терминал A: worker

```sh
npm run dev -- scheduler run
```

Команда занимает терминал до Ctrl+C. Оставьте её работающей.

## Терминал B: расписание

Для быстрого опыта укажите местное время не менее чем через две минуты от момента создания
расписания. В примере ниже время 18:00; запустите команду до 17:58 по Новосибирску или замените
`18:00` на ближайшее подходящее `HH:mm`.

```sh
npm run dev -- ask "создай ежедневную сводку погоды для Новосибирска: опрашивай каждые 10 секунд, публикуй каждый день в 18:00"
```

Ответ должен содержать ID `sch_…` и ближайшие сроки опроса и сводки. Первый опрос выполняется
через 10 секунд после создания расписания.

## В назначенное время

В терминале A появляется новая сводка. При её подготовке Agent вызывает
`get_weather_report_data`: фасад читает сохранённые опросы через MCP и передаёт модели показатели
за последние 24 часа. Worker проверяет ответ, сохраняет его в SQLite и выводит после сохранения.
Если MCP-вызова не было или ответ не прошёл проверку, вместо новой сводки появится причина ошибки;
предыдущий отчёт остаётся доступным.

Готовый текст можно прочитать отдельно:

```sh
npm run dev -- scheduler summary Новосибирск
```

Команда чтения не вызывает модель. Расписание работает, пока запущен `scheduler run`;
после закрытия терминала worker нужно запустить снова. Вывод идёт в терминал A, отдельной доставки нет.
