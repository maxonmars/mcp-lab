# Вызов Open‑Meteo MCP-инструмента

Цель: показать полный поток `ask → tool_calls → MCP → финальный ответ` с реальным Open‑Meteo API и
реальным DeepSeek.

## Требования

- Node 24 (локально проверено на установленной версии Node 22, см. ограничение ниже);
- установленные зависимости (`npm ci`);
- ключ `LAB_LLM_API_KEY` в окружении или корневом `.env`;
- доступ к сети для DeepSeek и Open‑Meteo. API-ключ самого Open‑Meteo не требуется.

## Список инструментов сервера (Inspector)

Из корня репозитория:

```sh
npx @modelcontextprotocol/inspector node servers/open-meteo/src/app/main.ts
```

Inspector подключается по stdio и в обычном режиме показывает только `get_current_weather` с его
input- и output-схемой. Три инструмента outfit-режима — в [демо совета по одежде](outfit.md).

## Ручной вызов инструмента

В Inspector (или другим MCP v2 client) вызовите `get_current_weather` с аргументом:

```json
{ "location": "Новосибирск, Россия" }
```

Успешный ответ содержит короткий текст на русском (место, локальное время наблюдения и часовой пояс,
состояние, температуру, ощущаемую температуру, влажность, осадки, ветер, единицы) и `structuredContent`
с теми же полями в нормализованном виде.

## Запуск через host

```sh
npm run dev -- ask "Какая сейчас погода в Новосибирске? Обязательно используй доступный инструмент и кратко объясни результат."
```

Ожидаемая служебная строка перед финальным ответом:

```text
MCP: get_current_weather — выполнено
```

Температура, время наблюдения и точный текст модели меняются между запусками, поэтому конкретный
ответ DeepSeek не фиксируется как ожидаемый результат — только факт вызова инструмента и формат
статусной строки.

## Сценарий isError

Города, которые Open‑Meteo geocoding не находит, приводят к `isError: true` от инструмента:

```sh
npm run dev -- ask "Какая погода в Плюторандии? Используй доступный инструмент."
```

Служебная строка в этом случае — `MCP: get_current_weather — ошибка`; MCP-результат с `isError` всё
равно передаётся модели вторым запросом, и модель формулирует финальный ответ сама (честно сообщает,
что данные не получены), а не получает решение от host.

## Что не входит в это демо

Автоматические тесты host и сервера офлайн: `apps/host/src/features/mcp/tests/toolSource.test.ts` и
`servers/open-meteo/src/tests/*.test.ts` используют подменённый SDK и подменённый `fetch`, без сети.
Настоящий stdio-процесс проверяется отдельно в `apps/host/src/features/mcp/tests/
openMeteo.integration.test.ts` — он получает список инструментов и закрывает Client, но не вызывает
`get_current_weather` и поэтому не обращается к Open‑Meteo. Только это демо и Inspector-сценарий выше
используют настоящий Open‑Meteo.

## Подтверждение

Оба сценария выше — успешный и `isError` — выполнены вручную с настоящим ключом DeepSeek и настоящим
Open‑Meteo. Фрагмент фактического успешного вывода:

```text
MCP: get_current_weather — выполнено

── Ответ агента ──

Сейчас в Новосибирске погода по данным инструмента такая:

- Состояние: преимущественно ясно
- Температура: 15.1°C, ощущается как 13.2°C
...
```

Точные числа и формулировки — из конкретного запуска и не являются гарантированным результатом
следующего вызова: температура и текст модели меняются, а служебная строка и порядок «статус → ответ»
фиксированы поведением.
