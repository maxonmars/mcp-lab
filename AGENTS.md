# mcp-lab

## Цель и текущий объём
Учебный репозиторий для развития собственного агента и изучения MCP.
Сейчас реализованы инкапсулированный Agent с CLI, tool calling с максимум одним MCP tool call за
реплику через собственные MCP-серверы Open‑Meteo и планировщика, worker планировщика погоды
(`scheduler run`, ADR 0004) с состоянием в SQLite сервера планировщика, пайплайн совета по одежде из
трёх MCP-инструментов Open‑Meteo (`outfit`, ADR 0005) и отдельное получение списка инструментов
локального Filesystem MCP. История, память, профили и экспериментальные режимы отсутствуют.
Направления курса — ориентир; они не разрешают реализовывать будущие задания заранее.
Перед заданием сформулируй учебную цель и минимальный результат; улучшения отдели явно.

## Зависимости
app связывает core, адаптеры и публичные входы фич.
core не импортирует SDK, Node API, адаптеры, app или фичи.
Фича не импортирует другую фичу; снаружи доступен только её index.ts.
Адаптер может реализовать публичный порт фичи; обратный импорт запрещён.
Специфический адаптер хранится внутри фичи, общий — в adapters.
Серверы не импортируют host или соседние серверы; host не импортирует серверы.
Один composition root на процесс. Регистрация явная, динамического поиска плагинов нет.
Текущая точка расширения — ModelPort. Другие контракты появляются под реальную задачу через ADR.
Новая фича использует контракт; не добавляй ветвление по её имени в core.

## Глоссарий
- Agent: объект, обрабатывающий реплику через ModelPort.
- Host: приложение, которое запускает MCP-клиент для конкретной фичи и в будущих заданиях может управлять другими клиентами.
- MCP client: соединение host с одним MCP-сервером; не LLM SDK.
- Worker: фоновый цикл `scheduler run` в процессе host; состоянием владеет MCP-сервер планировщика.
- Server: отдельный процесс или сервис, предоставляющий MCP-возможности.
- Tool source: заменяемый источник инструментов (`ToolSource` в core); реализация — MCP stdio.
- Context step: будущий именованный шаг подготовки контекста, сейчас не реализован.
- Command: пользовательская команда CLI/REPL; tool: действие, доступное модели.
- Agent turn: обработка реплики; MCP session: протокольная сессия соответствующей ревизии.
- Transport: способ передачи MCP-сообщений. Не называй разные понятия просто strategy.

## Конфигурация и команды
Реестр настроек: apps/host/src/app/settings.ts; описания: settings.md рядом.
Приоритет: defaults < YAML-файл < env < CLI. config show показывает источник.
Env и флаги выводятся из ключа. Секреты — только env, без значений в выводе и файлах.
process.env и process.argv читаются только в app/main.ts; дальше передаются явно.
Реестр команд: apps/host/src/app/commands.ts; один dispatch для CLI и REPL.
Справка и docs/configuration.md, docs/commands.md генерируются из реестров.
Лимиты — зарегистрированные настройки или именованные константы, не числа внутри цикла агента.

## Markdown и структура
Инструкции модели, заметки, память, журналы и отчёты — Markdown; метаданные — YAML frontmatter.
Структура допустима для API/MCP, схем инструментов, YAML-настроек и машинного состояния.
Не собирай смысловой контекст через JSON.stringify; схемы tool calling — отдельная граница API.
Текущий system prompt — app/system.md. Новые промпты фич — в их prompts/*.md.
При появлении состояния: кандидат → сохранение → замена; файл — временный рядом + rename.
Это не межфайловая транзакция. Не добавляй хранилища и миграции без задания.

## Guardrails и красные флаги
Перед фичей укажи контракт, папку, настройки, команды и тестируемый результат.
Нет подходящего контракта — остановись и предложи ADR, согласуй изменение ядра.
Обычная область PR: своя фича, composition root, документация; чужой код — с обоснованием.
Остановись и согласуй решение при if по фиче в ядре, расширении общего порта ради одной фичи,
импорте соседней фичи, обходе реестров, ручной справке, UI-тексте в ядре или промпте в TS/JSON.
dependency-cruiser проверяет границы, циклы и import type, включая workspace-импорты.
Пределы: 300 строк кода в файле, 400 в тесте, 60 в функции, 120 физических строк в AGENTS.md.
Исключение размера функции — только контейнер describe; it, hooks и helpers проверяются.
Фича содержит README.md, index.ts и tests/*.test.ts. prompts/ — только по необходимости.
Обход проверки или исключение требуют отдельного ADR; существующего allowlist нет.
Проверки семантики остаются частью review: автоматизация не доказывает назначение интерфейса.
Тесты без внешних API: fake ModelPort, подменённый fetch, временные каталоги.
Документация на русском. Комментарий — 1–2 строки о неочевидном факте; старые не переписывай без просьбы.
Устаревшие факты исправляй на месте. Причины ошибок и названия тестов должны быть точными.

## Definition of Done
- Минимальная цель задания выполнена; будущие направления не реализованы попутно.
- Содержательные тесты и npm run check проходят; границы не ослаблены.
- Документация и генерируемая справка актуальны; секреты не попали в файлы и вывод.
- Для наблюдаемого поведения есть короткое воспроизводимое демо в docs/demos.
- Измерения отделены от оценок и симуляций; ограничения названы явно.
