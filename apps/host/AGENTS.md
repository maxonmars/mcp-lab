# Правила host

Общие правила находятся в [корневом AGENTS.md](../../AGENTS.md).

- main.ts читает окружение и argv, compose.ts связывает зависимости.
- Agent хранит только модель и системную инструкцию; между вызовами respond() истории нет.
- Публичный порт ядра — ModelPort.complete(request: ModelRequest): Promise<ModelCompletion>; не добавляй методы ради будущих фич.
- Agent допускает максимум один MCP tool call за реплику (MAX_TOOL_CALLS_PER_TURN) и ровно один добавочный запрос модели после него.
- DeepSeek-специфичные параметры и SDK-типы не выходят из adapters/llm.
- CLI отображает AgentError, не печатает необработанные ошибки SDK или конфигурационные значения в ошибках.
- Команда описывается в app/commands.ts один раз; CLI и REPL используют один dispatcher.
- Настройки описываются в app/settings.ts; тексты справки и описания находятся рядом в .md.
- Не добавляй историю, reset, usage, память или новые MCP-инструменты без отдельного задания.
- Worker запускается только командой `scheduler run`; обработчик SIGINT — в main.ts, сигнал остановки передаётся явно.
- SQLite открывает только сервер планировщика; host работает с состоянием через MCP и не импортирует сервер.
- `ask` объединяет публичные инструменты Open‑Meteo и планировщика в app/toolSources.ts; лимит вызовов держит Agent.
- SDK-повторы отключены. Изменение этого поведения требует явного решения и теста числа вызовов.
- Тесты лежат рядом с модулем в tests; тесты сборки проверяют Markdown из другого cwd.
- npm run check выполняется из корня монорепозитория.
