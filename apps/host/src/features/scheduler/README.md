# Планировщик погоды: worker в host

## Назначение

Фоновый цикл `scheduler run`: опрашивает Open‑Meteo через MCP по расписаниям и выдаёт сводку за последние
24 часа. Интервальное расписание вызывает `ModelPort` с готовыми показателями; ежедневное запускает `Agent`,
который запрашивает показатели через фасад над MCP-портом планировщика. Готовый Markdown передаётся серверу
планировщика (`servers/scheduler`). Состояние (расписания, опросы, тексты) принадлежит серверу; фича не
открывает SQLite и не импортирует исходники серверов и соседнюю фичу `mcp`. Решения — в
[ADR 0004](../../../../../docs/adr/0004-scheduler-worker.md) и
[ADR 0006](../../../../../docs/adr/0006-daily-agent-weather-summary.md).

## Публичный контракт (`index.ts`)

- `runWorker(deps, signal)` — цикл. `deps`: `SchedulerPort`, `WeatherPort`, `ModelPort`, `Agent`, `Clock`,
  `WorkerEvents`, текст `systemPrompt` для интервальной сводки. `signal` — сигнал остановки от composition root.
- `SchedulerPort` — узкий порт состояния (`start`, `dueTasks`, `recordPoll`, `history`, `publishSummary`,
  `recordSummaryFailure`); `WeatherPort.observe(city)` возвращает структурированный результат, ошибка
  опроса — значение `{ ok: false, error }`, а не исключение.
- `openWorkerSession(config)` — два постоянных stdio-соединения worker (планировщик в режиме `--worker` и
  Open‑Meteo) и реализации портов поверх них; `close()` закрывает оба.
- `readSchedulerSummary(config, target)` — чтение сохранённой сводки через публичный `get_weather_summary`
  без модели и без worker; `target` вида `sch_` + 8 hex — ID, иначе город. Результат `not_found` содержит
  существующие расписания (`candidates`), `ambiguous` — подходящие; по ним команда подсказывает ID.
- `schedulerServerArgs(config, mode)` — аргументы запуска сервера (`public` или `worker`), `SchedulerError`,
  `systemClock`, `connectStdio` и типы событий.

Структурированный результат `get_current_weather` читается отдельным типизированным адаптером
(`weatherPort.ts`): `ToolSource` из `core` передаёт только текст. Ответы серверов проверяются по схемам zod.

## Настройки и команды

Composition root передаёт `scheduler.dbPath` и `scheduler.reportsDir` (абсолютными путями) и `mcp.timeoutMs`.
Команды: `scheduler run` (нужен `LAB_LLM_API_KEY`, занимает терминал до Ctrl+C) и
`scheduler summary <город|ID>` (ключ не нужен). В REPL — `/scheduler run`, `/scheduler summary …`.
Модельные инструкции: `prompts/weatherSummary.md` (интервальная сводка), `prompts/weatherAgent.md`
(ежедневная агентная сводка) и `prompts/scheduleTools.md` (для `ask`).

## Как работает цикл

Один последовательный цикл. Каждый тик: `dueTasks(now)`; для каждого расписания сначала опрос
(`get_current_weather`, результат или безопасная причина ошибки — в SQLite), затем сводка. Если сроки
совпали, сводка видит только что сохранённый опрос. Модель на шаге опроса не вызывается. Пока сроков нет,
worker ждёт не дольше `MAX_IDLE_WAIT_MS` (1 с): так он подхватывает расписание, созданное в терминале B.

Сроки назначает сервер: для интервальной сводки первый — `createdAt + интервал`, для ежедневной —
ближайшее заданное местное время после создания. После простоя просроченные опрос и сводка
выполняются по одному разу. Сводка не выполняется параллельно с опросами: на время генерации следующие
опросы ждут (после этого каждый выполняется один раз, догоняющих нет).

## Сводка

Период — последние 24 часа по UTC, границы включены. Считаются: запросы, успешные и ошибочные;
уникальные наблюдения по `observedAtUtc` (последний ответ слота); изменение, минимум, максимум и среднее
температуры по уникальным слотам. Без успешных наблюдений температурных показателей нет.

Модели уходит Markdown-контекст с вычисленными фактами и не более 8 примеров наблюдений
(`MAX_SAMPLE_OBSERVATIONS`), без сырых строк и без JSON. Для интервального срока это один запрос
`complete({ messages, tools: [], toolChoice: "none" })`. Для ежедневного срока `Agent.respond()` сначала
предлагает один `ToolSource`-фасад `get_weather_report_data`: вызов читает историю через MCP
`worker_get_history`, считает показатели и отдаёт контекст агенту. Агент делает второй запрос модели
с результатом инструмента; если инструмент не вызван, сводка не публикуется. Промпт требует начать ответ
строками `Период (UTC): <начало> — <конец>` и `Уникальных наблюдений: N`; host проверяет наличие и значения
этих строк (разметка вокруг них допустима).
Пустой ответ, ответ не текстом, неверный период или число наблюдений не публикуются: прежняя сводка
остаётся, причина фиксируется в SQLite и показывается в stderr, срок сдвигается, повторного запроса нет.

Отчёт: YAML frontmatter и заголовок добавляет host, содержательная часть — дословный текст модели.
Печать в терминале A выполняется только после подтверждения сохранения сервером.

## Остановка

Первый Ctrl+C (или SIGTERM) прекращает запуск новых операций; начатые опрос или генерация доводятся до
сохранения в пределах таймаутов `mcp.timeoutMs` и `llm.timeoutMs`, затем закрываются оба соединения.
Обработчик сигнала находится в `app/main.ts` и остаётся до конца остановки, включая закрытие соединений.
`npm run` пересылает SIGINT дочернему процессу, поэтому повторные сигналы в течение секунды считаются одним;
более поздний повторный Ctrl+C завершает процесс сразу, блокировку worker и соединения снимает ОС.

## Ограничения

Нет reconnect: если процесс сервера умер, опросы записываются как ошибки, а недоступность планировщика
завершает цикл ошибкой. Нет автозапуска — после закрытия терминала или перезагрузки worker запускают вручную.
История 24 часа читается целиком: при интервале 10 секунд это до 8 640 строк на сводку.

## Проверка

`tests/worker.test.ts` и `worker.stop.test.ts` — fake-часы, in-memory порт планировщика, fake `ModelPort`
(шесть опросов за минуту, один вызов модели, граница, дедупликация, некорректные ответы, простой, Ctrl+C
во время опроса и генерации, второй worker). `summary.test.ts` — показатели, контекст, проверка ответа,
отчёт. `mcp.test.ts` — адаптеры с подменёнными клиентами. `integration.test.ts` — те же сценарии с
настоящим процессом `servers/scheduler` (SQLite во временном каталоге), без внешних API.
